## Documento de Arquitetura e Especificação Funcional

Versão: 1.0

Autor: Enzo Martins

---

# 1. Objetivo

O Sistema de Controle de Chamados Internos tem como objetivo centralizar o registro, acompanhamento e distribuição de solicitações internas realizadas pelos colaboradores de uma empresa.

A solução visa substituir controles informais realizados por e-mail, WhatsApp, planilhas ou anotações manuais, proporcionando rastreabilidade, organização e melhor distribuição de trabalho entre os responsáveis pelo atendimento.

# 4. Justificativa Tecnológica

A escolha do Laravel permite construir uma aplicação completa utilizando uma única base de código.

O uso de Blade reduz a complexidade da aplicação, eliminando a necessidade de manter um frontend desacoplado para um sistema predominantemente CRUD.

TailwindCSS foi escolhido para acelerar o desenvolvimento da interface e garantir consistência visual.

SQLite foi adotado para facilitar a execução local por qualquer avaliador sem necessidade de configuração adicional.

# 5. Arquitetura da Solução

## Arquitetura Monolítica Modular

O sistema será desenvolvido utilizando uma arquitetura monolítica organizada por responsabilidades.

Fluxo principal:

```text
View
 ↓
Controller
 ↓
Form Request
 ↓
Service
 ↓
Model
 ↓
Database
```

Essa abordagem reduz a complexidade operacional e facilita a manutenção por equipes pequenas.

# 7. Padrões de Projeto Utilizados

Isolar regras de negócio dos Controllers.

Exemplo:

```text

```

Responsável pela distribuição automática de chamados.

# 8. Princípios de Desenvolvimento

## SOLID

### Single Responsibility Principle

Cada classe terá apenas uma responsabilidade.

Exemplo:

```text

↓
Controla requisições

TicketAssignmentService
↓
Realiza distribuição automática
```

---

### Open Closed Principle

Enums e Services permitirão expansão sem alterações significativas.

---

### Liskov Substitution Principle

Respeitado através das abstrações nativas do framework.

---

### Interface Segregation Principle

Aplicado conforme necessidade futura.

---

### Dependency Inversion Principle

Dependências serão resolvidas pelo container do Laravel.

---

Toda lógica reutilizável será extraída para:

* Services
* Components
* Helpers
* Scopes

Não serão implementadas funcionalidades desnecessárias ao escopo.

# 11. Regras de Negócio

## RN01

Todo chamado deve possuir:

* Título
* Descrição
* Prioridade
* Responsável

---

## RN02

O sistema deverá registrar automaticamente:

```text
Data de abertura
```

---

## RN03

Chamados podem ser atribuídos:

* Manualmente
* Automaticamente

---

## RN04

A distribuição automática deve selecionar o responsável com menor quantidade de chamados em aberto.

---

## RN05

São considerados chamados em aberto:

```text
ABERTO
EM_ANDAMENTO
```

---

## RN06

São considerados chamados concluídos:

```text
RESOLVIDO
FECHADO
```

---

## RN07

Em caso de empate na distribuição automática:

Selecionar o responsável com menor ID.

# 12. Casos de Uso

## UC01 – Realizar Login

### Ator

Usuário

### Fluxo Principal

1. Informa e-mail
2. Informa senha
3. Sistema valida credenciais
4. Usuário acessa dashboard

### Resultado

Usuário autenticado.

---

## UC02 – Abrir Chamado

### Ator

Usuário

### Fluxo Principal

1. Acessa tela de novo chamado
2. Preenche dados
3. Seleciona responsável ou distribuição automática
4. Salva

### Resultado

Chamado criado.

---

## UC03 – Distribuição Automática

### Ator

Sistema

### Fluxo Principal

1. Usuário escolhe atribuição automática
2. Sistema contabiliza chamados abertos
3. Identifica responsável menos carregado
4. Atribui chamado

### Resultado

Chamado distribuído automaticamente.

---

## UC04 – Editar Chamado

### Ator

Usuário

### Fluxo Principal

1. Abre chamado
2. Altera informações
3. Salva

### Resultado

Chamado atualizado.

---

## UC05 – Alterar Status

### Ator

Usuário

### Fluxo Principal

1. Acessa chamado
2. Seleciona novo status
3. Salva

### Resultado

Status atualizado.

---

## UC06 – Consultar Chamados

### Ator

Usuário

### Fluxo Principal

1. Acessa listagem
2. Visualiza chamados
3. Aplica filtros

### Resultado

Lista filtrada.

## UC07 – Visualizar Detalhes
